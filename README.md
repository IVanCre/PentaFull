# MessagaFull

Данный проект -это клиент-серверный мессенджер.
Реализованный функционал смотрите по коммитам.
Автообновление клиента реализовано через сервер, в обход GooglePlay.


+ Penta_Server- сервер в виде windows-службы.
+ Penta_CleintLib - библиотека-ядро клиента.
+ MessageLib - библиотека описывающая сущность Сообщения и связывающая проекты Penta_Server и Penta_CleintLib.
+ Client - кроссплатформенный клиент на MAUI. Приоритет отдан для android(остальное не делал). Является надстройкой над Penta_CleintLib.

Основная передача данных между клиентом и сервером идет через signalR c аутентификацией по jwt-токенам.
Часть первичных запросов реализованы на https(регистрация и админ-функции).
Пуш-оповещения идут через гугловскую firebase(https://console.firebase.google.com/project/имя_вашего_проекта/settings/serviceaccounts/adminsdk)
Для отладки-управления сервером используется web-морда swagger.

Хранение данных на сервере осуществляется через EF( на 16.04.2026 это mssql)
Хранение данных на клиенте осуществляется через SQLite.

Для тестирования используется TestUtils\ConsoleClient_Tests - упрощенная консольна реализация Client.
Единовременно может работать 1 экземпляр коносль-клиента, т.к. создается БД SQLite по адресу C:\Users\user\AppData\Roaming\PentaClientDB.db3
Автотесты ПОКА не пишу, т.к. разработку веду в одно лицо.
В локальном гите веду 1 ветку, чтоб можно было откатиться при случае.

Для шифрования канала используется самоподписной сертификат, который физически лежит в папке с сервером
Логин/Пароль админа для серверной админки в swagger: admin_1991/validPass_917

Ввиду того, что сервак запускается как сервис из конкретной папки на ПК, то и сборки сервера и клиента должны лежать в одной корневой папке.
Это нужно, чтобы при запросе у сервера свежей сборки клиента, сервер смог ее найти(......\ClientReleases\Android\ваша_сборка.apk).
